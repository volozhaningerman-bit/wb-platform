## Загрузка исправлений

Архив содержит только изменённые/новые файлы. Распаковать и загрузить его содержимое в корень GitHub-репозитория. Директории .github, apps и docs сохранить. Ничего вручную удалять не требуется.

## Railway: сервис wb-platform-web

1. Settings → Scale → Regions & Replicas: заменить недействительный sfo на доступный регион, предложенный Railway. Сохранить. Это отдельный блокер, который архив не исправляет.
2. Settings → Source: репозиторий wb-platform, ветка main; Root Directory оставить пустым (корень репозитория).
3. Variables: добавить RAILWAY_DOCKERFILE_PATH со значением Dockerfile.web.
4. Settings → Build: удалить Custom Build Command с pnpm. Dockerfile содержит установку и сборку. При наличии выбора Dockerfile в Builder выбрать его. Переменная выше задаёт нужный файл для Docker-сборки.
5. Settings → Deploy: удалить Custom Start Command с pnpm. Команда запуска уже содержится в Dockerfile (npm start из /app/apps/web).
6. Healthcheck Path: /api/health.
7. Watch Paths: удалить ограничение apps/web/** либо добавить также /Dockerfile.web, /package.json, /.dockerignore и /railway.json. Проще временно оставить без ограничения.
8. Применить изменения и запустить новый deploy последнего main. Проверить, что лог использует Dockerfile.web и npm ci, а не pnpm.
9. После успешного запуска: Settings → Networking → Generate Domain. Открыть полученный домен /dashboard. Если Railway запрашивает порт, использовать фактический порт из лога запуска.

В railway.json оставлена только схема: выбор Dockerfile и остальные настройки задаются в сервисе. Это не зависит от доступности устаревающей функции Config as Code для новых сервисов.

API-сервис — отдельная незавершённая заготовка. Этот Dashboard от него не зависит. Не применяйте web-настройки к api; ошибки api не означают, что web не может работать самостоятельно.

Демо не требует базы данных, WB-токена или авторизации. Настройки Railway по скриншотам не были изменены автоматически. Успешный деплой и домен нужно подтвердить отдельно.
