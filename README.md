# WB Platform — кабинет руководителя

Рабочая desktop-демонстрация управленческого Dashboard на Next.js. Продажи, реклама, план, категории, менеджеры, контроль отклонений. Данные фиксированы на 7 сентября 2026 года и **не получены из WB**.

## Запуск

Node.js 22.13+ (рекомендуется актуальная Node 22 LTS), npm:

```bash
npm ci --prefix apps/web
npm run dev
```

Открыть http://localhost:3000/dashboard. Главная `/` перенаправляет в кабинет.

```bash
npm test
npm run typecheck
npm run build
npm start
```

Устанавливать зависимости нужно в `apps/web`: там находится проверенный `package-lock.json`. Корневые команды делегируют в web; старые turbo/pnpm-конфигурации не являются текущим способом запуска. API-приложение — незавершённая заготовка и в этот web-релиз не входит.

## Что работает

- Периоды 7/14/30 дней и сравнение с предыдущим периодом той же длины.
- Совместные фильтры по магазину и менеджеру, включая «Без менеджера».
- Круги: категории → подкатегории → товары; менеджеры → категории → подкатегории → товары. Возврат по пути, легенда с кнопками, точные суммы и доли внутри выбранной группы.
- Динамика продаж/рекламы, доступная таблица значений по дням.
- Результаты менеджеров, поиск и сортировка товаров, карточки разбора.
- Сигналы по ДРР, остаткам и плану. Сигналы не доказывают вину сотрудника.
- CSV выгружает товары с текущими общими фильтрами, поиском и сортировкой.
- `/api/health` возвращает `{ "status": "ok", "mode": "demo" }`.

## Правила расчёта

Продажи — сумма демонстрационных выкупленных единиц × цена; возвратов в наборе нет. Прибыль = продажи − себестоимость − комиссии/логистика − реклама, без налогов и общехозяйственных расходов. ДРР = реклама / **все продажи**, а не только рекламные заказы. При нулевой базе процент не рассчитывается. Остаток берётся из последнего дня; покрытие = остаток / среднее количество продаж в день. Все денежные значения демо — целые рубли.

Один товар закреплён за одним менеджером. В демо назначения не меняются. Для реальной интеграции нужны назначения с историей дат, дедупликация операций WB, возвраты, завершённость синхронизации и сверка финансовой отчётности. Пороги демо: ДРР >15%, остаток <7 дней, план <80%.

## Railway

Подробные действия: [восстановление запуска](docs/railway-launch-repair.md).

Используйте сервис wb-platform-web с корнем репозитория и переменной RAILWAY_DOCKERFILE_PATH=Dockerfile.web. Удалите старые pnpm-команды Build/Start в настройках сервиса. Замените недействительный регион sfo на доступный. Healthcheck: /api/health.

Демо не требует DATABASE_URL или WB-токена. API-приложение пока не готово и для этого кабинета не требуется. Настройки и факт публикации Railway проверяются отдельно от локальной сборки.
